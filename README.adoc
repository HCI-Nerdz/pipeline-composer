== Idea



If a system applies rules in order, the primary UI should be one ordered map:



* Sequence at the root

* Parallelism nested inside composite steps

* Insert-between with *typed* sockets (only valid rule kinds)

* Path replay on the same map



== Architecture



The repo is layered so the demo is one *adapter* over shared logic — not a mythical cross-framework UI compiler.



[source]

----

src/core/           pipeline IR: types, acceptedKinds, evaluation, replay, serialize

src/controller/     headless interaction state + actions (framework-agnostic TS)

src/ui/render.ts    DOM string renderer (first adapter view)

src/main.ts         binds DOM events → controller; subscribes → paint

----



* *Core* holds the shared intermediate representation: pipeline documents, typed insertion rules, path replay, and JSON serialize/parse helpers.

* *Controller* owns selection/insert-at, palette open, sample URL, evaluation result, and highlight ids. Actions: `setScenario`, `setSampleUrl`, `openInsertAt`, `insertStep`, `closePalette`, `replay`.

* *Adapters* are thin: map controller state to a renderer and wire user input back to actions.



Future adapters (React, Solid, web components, canvas) would reuse `core` + `controller` unchanged; only the view layer swaps.

== HCI Nerdz demo chrome



Project demos hosted at `https://hci-nerdz.github.io/<project>/` need a *minimal org link-back* — not a cloned Astro site header or sticky nav bar. Prefer a hero breadcrumb eyebrow on the same line as the pattern label, e.g. linked **HCI Nerdz** · Processing map above the demo title.



* Use a divider (· or similar) between the org link and the pattern/category label.

* Keep each demo’s own theme; shared design tokens are optional, not required.

* Full site navigation lives on the org site. True uniformity later may come from embedding demos as Astro routes/islands — not copying headers across Vite demos.



Sharing a full header package across the Astro site and Vite demos is optional; breadcrumb link-back plus shared tokens is enough until demos are hosted under the org site.



This demo implements the breadcrumb in `src/ui/render.ts` (`eyebrow-link` · `eyebrow-label`).
